heading(doc,'5. Diseño de la solución',1)
sub('5.1 Arquitectura general','Learn2Code sigue una arquitectura web cliente-servidor. El navegador ejecuta el frontend y consume una API REST bajo /api/v1. El backend coordina reglas, persistencia y proveedores externos. Esta separación permite que las decisiones críticas se mantengan del lado del servidor y que la interfaz se concentre en navegación, formularios y presentación.')
add_figure(doc,DIAG/'01_arquitectura_general.png','Figura 3. Arquitectura general de Learn2Code.',6.45)
sub('5.2 Arquitectura frontend','El frontend está desarrollado con React y Vite. React Router administra las rutas públicas y protegidas. La sesión se expone mediante la capa de autenticación y existen componentes de control como ProtectedRoute, VerifiedEmailRoute y LearningFlowGate. La aplicación separa páginas, componentes reutilizables y módulos de acceso a API.')
sub('5.3 Arquitectura backend','El backend es un monolito modular. Cada dominio reúne rutas, controladores, servicios, repositorios, validadores, errores y pruebas según la necesidad del módulo. La organización Controller-Service-Repository evita mezclar HTTP, reglas de negocio y SQL dentro del mismo archivo.')
add_figure(doc,DIAG/'02_backend_capas.png','Figura 4. Capas principales del backend y sus responsabilidades.',5.9)
sub('5.4 Comunicación cliente-servidor','El frontend envía solicitudes HTTP y recibe JSON. Los recursos que requieren sesión usan el token de acceso; el proceso de refresh permite renovar el acceso sin obligar a iniciar sesión en cada vencimiento. Las cookies y la política CORS se configuran con credenciales cuando el flujo lo necesita.')
sub('5.5 API REST','La API se versiona con el prefijo /api/v1. Los recursos se organizan por dominio: auth, dashboard, diagnostics, onboarding, exercises, gamification, learning-paths y student-routes. Los métodos HTTP se eligen según la intención: GET consulta, POST crea o ejecuta una acción, PUT reemplaza/establece un estado y PATCH modifica parcialmente datos existentes.')
sub('5.6 Persistencia de información','PostgreSQL mantiene usuarios, perfiles, sesiones, diagnósticos, rutas, ejercicios, intentos, preferencias y otros datos del sistema. El esquema se modifica mediante node-pg-migrate para conservar un historial reproducible. Esto evita depender de cambios manuales realizados directamente desde un administrador de base de datos.')
sub('5.7 Redis','Redis funciona como almacenamiento rápido para información temporal o de apoyo. Su uso permite evitar que ciertos datos temporales tengan que persistirse siempre como filas relacionales.')
sub('5.8 Seguridad','La seguridad se aborda en varias capas: Helmet configura cabeceras, CORS restringe el origen permitido, Express limita el tamaño del JSON, Zod valida entradas y los middlewares protegen rutas. Las contraseñas se procesan con bcryptjs y los tokens se manejan con jose. Las operaciones sensibles, como verificación y cambio de correo, incorporan controles de cuota.')
sub('5.9 Estructura de carpetas','La estructura del repositorio separa frontend, backend, database, docs e infraestructura. Esta separación hace más sencillo ubicar una responsabilidad sin recorrer archivos no relacionados.')
